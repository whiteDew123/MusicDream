# 微信小程序播放前台 · 开发规范

> **版本**：v1.0（草案）　**适用项目**：MusicDreamer 微信小程序播放前台
> **目的**：作为后续所有小程序开发的**统一依据**，覆盖目录、命名、设计、代码、网络、播放器、接口对接、安全、性能、提交与上线规范。
> **关联文档**：`frontend-design-standards/design-stripe.md`、`Design-standards.md`、`animation.md`、`performance-optimization.md`；后端接口对齐 `playerFront/src/api/*.js`。

## 0. 文档约定

- 本文档用到的**颜色 token、间距、圆角、阴影、字体**均以 `frontend-design-standards` 为准，小程序端通过 `app.wxss` 的 CSS 变量映射（见 §5）。

## ⚠️ 全局铁律 · 开发全程不影响已有功能

> **总原则**：微信小程序开发期间，**不得破坏或回退任何已上线/已存在功能的实现**——包括 Web 播放前台（`playerFront`）、管理后台（`adminFront`）与后端微服务（`musicBack`）。小程序是**新增客户端**，不是对既有功能的改造。

**强制要求：**

1. **增量不改**：后端**只新增**接口/字段，不改动既有接口的路径、参数、返回结构、鉴权逻辑；新增能力用**新前缀/新路径**，不占用已有路由。
2. **前端隔离**：小程序的代码、配置、资源与 `playerFront`/`adminFront` 互相独立，不共用目录、不修改对方的文件；可复用的**契约/常量**通过新文件在本地实现，不侵入原项目。
3. **设施不动**：不改动影响现有功能运行的基础设施——网关路由表（`music_gateway`）、Nacos 注册、认证鉴权、既有数据库表结构与字段、既有配置文件。
4. **确需改动要**：先在本文档/需求中**注明影响面与理由**，经评审并**兼容地**实现（字段只加不改、接口默认值兜底），确保存量数据与 Web 端不受影响。
5. **回归验证**：每次改动后对已有功能做冒烟验证（登录、推荐、搜索、播放、歌单、收藏、评论、消息、设置），确认无回归后再提交。
6. **双端兼容**：小程序与 Web 端共用同一后端接口时，遵循**只增不减、字段只加不改**，保证两个客户端都能正常工作。
7. **白名单与新增依赖**：新增的微信登录等接口、新配置，走"新加、不动旧"原则，仅在网关/`application.yml` 处**追加**配置，不覆盖既有值。

**违反处理**：若不可避免要触碰既有功能/代码，必须暂停并向需求方说明，**不允许静默改动**。

## 1. 技术栈与体系

| 项 | 决定 | 说明 |
|---|---|---|
| 客户端 | **原生小程序**（WXML / WXSS / JS） | 无第三方构建链，对后台播放/录音/分享等原生能力控制最稳 |
| 登录方案 | **微信一键登录** + 兼容邮箱/密码登录 | `wx.login` → 后端 `POST /api/login/wx` 换 openid → 签发同一套 JWT |
| 后端接入 | 复用现有 Spring Cloud 网关 `music_gateway`（默认 `9000`） | 小程序作为新客户端，**不重写后端** |
| 鉴权 | `Authorization: Bearer <JWT>` | 与 Web 端一致；统一响应 `Result{code, message, data}` |
| 后端新增 | 需新增 `POST /api/login/wx` 微信授权接口 | 详见 §3 |
| 通用组件 | 原生自建 + `Vant Weapp` | 补齐按钮/弹层/下拉刷新/骨架屏等能力 |

**架构分层（小程序侧）：**

```
页面层（pages）      登录/发现/搜索/排行/歌手/歌单/播放器/我的/胶囊/识曲/消息/设置
   ↓
业务 API 层（api）   每个模块一个文件，直接对齐后端 URL 与字段
   ↓
状态层（utils）      播放器 store（InnerAudioContext + 歌词 + 播放模式）
   ↓
网络层（utils/request.js）  wx.request 封装：baseURL + token + Result/401 处理
```

## 3. 登录与鉴权规范

### 3.1 登录流程（微信一键登录，推荐）

```
小程序启动
  → wx.login() 获取 temp code
  → POST /api/login/wx    body: { code }
  → 后端 code2session 换 openid → 查/建用户 → 签发 JWT
  → 返回 { token, userId, username, role, imageUrl, openid, isNewUser }
  → setStorageSync(token/userInfo)
```

- **登录态判断**：全局 `app.js` 启动时读 `storage` 的 token，存在即可放行；不存在跳 `pages/login/login`。
- **首次登录建号**：后端按 `openid` 建匿名用户（默认昵称"音乐爱好者"+ 默认头像），前端仅用 `isNewUser` 视情况引导补充资料。
- **token 刷新**：`Result.code === 401` 时清除本地登录态并跳登录页。
- 端点需在网关白名单放行 `/api/login/wx`（无需 token）。

### 3.2 兼容邮箱/密码登录

保留 Web 端接口 `POST /api/login`（`{ account, password }`）与 `POST /api/register`，两者与微信登录**签发同一套 JWT**，实现账号互通。

### 3.3 Token 与用户信息存储键名（统一约定）

| 键名 | 内容 |
|---|---|
| `MD_TOKEN` | JWT 字符串 |
| `MD_USER_INFO` | `{ userId, username, role, imageUrl }`（对象字符串化） |
| `MD_CURRENT_PLAYING` | 播放器恢复用的最近一次播放歌曲（可选） |

> token 存放使用 `wx.setStorageSync`；**严禁**把 token 明文写进日志或 URL 参数。

## 5. 设计规范（视觉 + 交互）

### 5.1 视觉 token（对齐 design-stripe + Design-standards · 亮色版）

小程序 `app.wxss` 用 CSS 变量承载，页面 `wxss` 一律引用变量而非裸值。

```css
page {
  /* 品牌色（应用端统一） */
  --brand-primary: #5e5ce6;          /* Stripe 紫：CTA/高亮/播放按钮 */
  --brand-primary-hover: #4a3fcf;    /* 悬停加深 */
  --brand-primary-soft: #b9b9f9;     /* 浅紫：标签底色/选中态底 */
  --brand-accent: #4353ff;           /* Webflow 蓝（管理端，小程序不用） */

  /* 亮色基底 */
  --bg-page: #f6f9fc;                /* 页面底色 */
  --bg-card: #ffffff;                /* 卡片底色 */
  --bg-subtle: #f0f4f8;              /* 列表项悬停/输入框底 */
  --bg-skeleton: #e8ecf0;            /* 骨架屏 */

  /* 文字 */
  --text-primary: #1a1a1a;           /* 主文字 */
  --text-secondary: #6b7280;         /* 辅助文字 */
  --text-muted: #9ca3af;             /* 弱化/占位 */

  /* 描边 / 阴影 */
  --hairline: #e3e8ee;               /* 1px 卡片边框 */
  --hairline-input: #a8c3de;         /* 输入框边框 */
  --shadow-card: 0 4px 20px rgba(0,0,0,0.06);      /* 卡片轻阴影 */
  --shadow-hover: 0 4px 20px rgba(0,0,0,0.08);     /* 悬停 */

  --radius-sm: 6px;                  /* 输入框/小元素 */
  --radius-md: 8px;                  /* 紧凑卡片 */
  --radius-lg: 12px;                 /* 卡片/容器 */
  --radius-pill: 9999px;             /* 按钮/标签 */

  --space-2: 2px;  --space-4: 4px;  --space-8: 8px;
  --space-12: 12px; --space-16: 16px; --space-24: 24px; --space-32: 32px;
}
```

**颜色使用原则：**
- `--brand-primary` 用于**主按钮、当前播放竖条、歌词高亮、播放类图标**，克制使用，一屏一个主 CTA。
- 页面底色统一 `--bg-page`，卡片统一 `--bg-card`，描述文字用 `--text-secondary`。
- **不用纯黑** `#000` 作正文；错误态用 `#ea2261`（ruby），成功用 `#10b981`，警示 `#f59e0b`。

### 5.2 字体排版（小程序）

- 小程序不加载自定义字体，系统字体分层：
  - 大标题 32~36rpx / 600；本节标题 30rpx / 600；卡片标题 28rpx / 500；正文 26~28rpx / 400；辅助 24rpx / 400；注释 22rpx / 400。
- 播放量、时长等**数字**建议用等宽数字（小程序无 `tnum`，可用 `font-variant-numeric: tabular-nums` 近似）。
- 行高：正文 1.4~1.6；标题 1.2~1.3。

### 5.3 交互规范（对齐 animation.md · 亮色适配）

| 场景 | 行为 | 规格 |
|---|---|---|
| 播放/暂停 | 图标弹性缩放，模拟"启动音乐" | `scale(0.85→1.1→1)`，350ms `ease-out` |
| 进度条拖拽 | 滑块圆点放大 1.3 倍，拖拽显示时间戳 | 圆点过渡 150ms；时间戳跟随 100ms |
| 上/下一首 | 歌曲信息滑出 → 新歌滑入 | 滑出 200ms `ease-in`，滑入 250ms `ease-out`，间隔 50ms |
| 歌词滚动 | 随进度自动滚动，当前行高亮且居中 | 高亮用 `--brand-primary`；用 `scroll-view` + `scroll-into-view` |
| 卡片点击 | 当前播放项左侧出现紫色竖条 | 宽 4~6rpx，出现 200ms `ease-out` |
| 点赞/收藏 | 心形图标弹跳 | `scale(0.6→1.3→1)`，400ms |
| 页面切换 | 淡入淡出 | 250ms `ease-out` |
| 骨架屏 | 列表/卡片优先显示 | 底色 `--bg-skeleton`，透明度 0.5↔1 循环 1.2s |
| Toast | 底部滑入轻提示 | 350ms `ease-out`，停留 3s |
| 危险操作 | 二次确认弹层 | 背景遮罩 200ms 淡入 |
| 下拉刷新 | 顶部紫色旋转环 | 800ms 循环 |

### 5.4 触摸目标（小程序关键）

- 所有可点击元素**最小触摸区域 ≥ 88rpx（≈44px）**，避免误触。
- 按钮高度建议 **≥ 80rpx**；表单输入框高度 **≥ 80rpx**。
- 列表项左侧留出足够点击区，勿让实际点击区过小。

## 6. 代码规范

### 6.1 WXML

- 用 `wx:if`/`wx:else` 控制显隐；用 `wx:for` 渲染列表，**必须给 `wx:key`**（唯一 id 或 `*this`）。
- 列表项 `data-*` 传参，事件 `bind:tap="onXxxTap"`。
- 复杂切换用 `wx:key` + `hidden`（保留状态）而非频繁 `wx:if`。
- **禁止**在 WXML 中写复杂逻辑与多处重复；抽到 `wxs` 或 JS 计算属性。
- 图片懒加载：`<image lazy-load>`。长列表用 `scroll-view` 或分页。

### 6.2 WXSS

- 使用 **rpx** 作为尺寸单位（设计稿按 750rpx 宽出稿）。
- 全局/组件样式用 `app.wxss` + 组件 `wxss`；页面样式加页面前缀防串扰。
- `page` 统一设置背景 `--bg-page`；卡片统一 `--bg-card` + `--shadow-card`。
- `transition`/`animation` 控制在 150~400ms，避免卡顿。
- 大图背景、复杂阴影少用；图片用 `mode="aspectFill"` 保证封面裁切。

### 6.3 JS

- 页面用原生 `Page({ data, onLoad, onShow, ... })`；组件用 `Component({ properties, data, methods })` 并 `options: { styleIsolation: 'apply-shared' }`。
- 逻辑抽到 `utils/` 复用，页面保持薄。
- `data` 只放渲染需要的字段；**`setData` 最小化**，避免整页大对象。
- 异步统一 `async/await`；`wx.request` 用 `promisify` 封装（见 §7）。
- 定时器、录音、播放器等在 `onUnload/onHide` 记得清理。

### 6.4 错误处理

- 所有请求需 `catch`；网络层统一 `Result.code !== 200` 处理，业务层**不重复弹窗**。
- `console` 时序：开发用 `console.log/debug`，上线可保留 `console.warn/error`，避免敏感信息。

## 7. 网络层规范（`utils/request.js`）

- **唯一出口**：所有 API 函数必须经由 `request.js` 的封装方法，禁止页面内直接 `wx.request`。
- **baseURL**：从 `config/index.js` 读取网关 HTTPS 地址（如 `https://api.example.com/api`）。开发期可在开发者工具勾选"不校验合法域名"。
- **token 注入**：请求拦截器自动加 `Authorization: Bearer <token>`；无 token 且非白名单接口时按未登录处理。
- **统一成功**：`res.code === 200` 才 resolve 数据；否则 reject 并 toast（可用 `silent: true` 静默）。
- **401 处理**：`res.code === 401` 时清登录态、跳登录。
- **超时/重试**：默认 `timeout 10000`；上传类（识曲）设 `15000`+。
- **并发/loading**：页面级统一 `showLoading`/`hideLoading`，避免重复提示。

> 微信小程序 `InnerAudioContext.src`、`uploadFile`、`downloadFile` 的域名都需在上线前配置到小程序后台合法域名。

## 9. 播放器开发规范（核心）

### 9.1 音频引擎

- 用 **`wx.createInnerAudioContext()`** 创建**全局唯一**播放实例，放在 `utils/player.js`（单例），供所有页面共用。
- 不再引入 Web 端 `HTML5 Audio`。`src` 赋值使用 `musicUrl`（须可访问的 HTTPS）。
- 循环模式：顺序（`ended` 下一首）、单曲（`loop=true`）、随机（随机索引），对齐 Web 端 `playMode: 0/1/2`。

### 9.2 后台播放

- `app.json` 必须配置：`"requiredBackgroundModes": ["audio"]`，并调用 `wx.setInnerAudioOption({ obeyMuteSwitch: false })` 允许静音键下播放。
- iOS 对类型/时长有要求，需真机重点验证后台与锁屏控制。

### 9.3 歌词

- 移植 Web 端 LRC 解析逻辑（`src/api/music` 返回的 `lyric` 可能为文本或文件路径），输出 `[{ time, text }]` 升序。
- 渲染用 `scroll-view` + `scroll-into-view`，当前行高亮 `--brand-primary` 并居中。

### 9.4 全局 MiniPlayer

- `mini-player` 组件挂到 tab 页底部悬浮（tabBar 之上），常驻显示当前歌曲+播放/暂停+切歌，点击进全屏 `pages/player/player`。
- 播放状态用全局单例，各页面通过 `getApp().player` 或观察 `player` 变化刷新。
- 页面进入 `onShow` 时同步一次播放状态，避免状态不一致。

### 9.5 生命周期

- 后台/锁屏按微信规则；`onUnload` 关播放器或仅暂停，避免静默播放资源。

## 10. 样式隔离与组件规范

- 组件用 `Component` 并在 `options.styleIsolation` 中按需隔离：
  - 全局样式类：`apply-shared`（页面样式渗入组件）。
  - 完全隔离：`isolated`（默认）。
- 组件对外用 `properties` + `events` 通信，避免直接 `getApp()` 或全局变量耦合（播放器除外，允许全局单例）。
- 通用组件在 `components/` 下按目录组织，样式独立。

## 11. 安全与数据规范

1. **token 本地存储**，不放 URL、不入日志；退出登录清空。
2. **接口鉴权**：登录态接口必须带 token；后端已有 JWT 鉴权，前端不自行绕过。
3. **域名白名单**：上线前把 `request / uploadFile / downloadFile` 域名加入小程序后台合法域名。
4. **敏感信息**：邮箱、手机号等展示做脱敏（如 `138****1234`）。
5. **不采集**未授权的用户画像；尊重隐私与`用户信息保护指引`。

## 12. 性能与包体积

| 项 | 约定 |
|---|---|
| 分包 | 主包只留必要页；特色功能（识曲/胶囊）可拆**分包**，遵守 2M/单包限制 |
| 图片 | 封面用 `aspectFill` + `lazy-load`；资源尽量用 CDN/压缩，避免大图 |
| 数据 | `setData` 最小化、合并；长列表用 `scroll-view` 或分页 + 骨架屏 |
| 请求 | 可缓存数据用 storage 缓存（排行榜等低频）；下拉刷新时才重新拉取 |
| 渲染 | 复杂动画用 CSS + `transform`，避免 JS 高频 `setData` |

## 附录 A · 功能清单与一期/二期划分

> 决策：**一期做核心闭环（模块 1–4），特色功能（胶囊/听歌识曲）放二期**；tabBar 采用 **4 tab：首页 / 搜索 / 歌单 / 我的**。
> 范围对齐 Web 端全功能，但排除 Web 独有/后端暂无项。

### 一期（核心闭环，先上线）

**① 账号与登录**
- 微信一键登录（`wx.login` → `POST /api/login/wx`）；兼容邮箱/密码登录、注册（邮箱验证码）；登录态管理、退出、401 跳登录。

**② 内容浏览（tab：首页/搜索/歌单）**
- 首页·推荐（`recommend/songs`）、搜索（`music/search`）+ 本地搜索历史、排行榜（`music/rank`）
- 歌手列表 / 歌手详情（`singer/recommend/artists`、`singer/detail`）
- 歌单列表 / 歌单详情（`songList/public/*`）、歌曲详情（`music/{id}`）

**③ 播放器（核心体验）**
- 全屏播放页（播放/暂停、上/下一首、进度条拖拽、播放模式切换、收藏/评论/分享入口）
- 歌词滚动（当前行高亮居中）、全局迷你播放条 MiniPlayer（tab 常驻，点击进全屏）
- 后台/锁屏播放；播放列表三模式（顺序/单曲/随机）

**④ 用户互动与我的（tab：我的）**
- 我喜欢的音乐（`like/music`）、收藏/创建歌单（`like/list`、`songList/my`、歌单增删歌）
- 点赞（`like/song/{id}` toggle）、评论（列表/发表/删除/计数，扁平单层）
- 分享（`onShareAppMessage` + `share/music/{id}`）、消息通知（`msg/my`、未读数、标记已读）
- 设置（改资料/头像/密码）、我的聚合页

> 一期 tabBar：首页(推荐) / 搜索 / 歌单 / 我的，配套全局基建（网络层、加载/空态/骨架屏、下拉刷新、分页）。

### 二期（特色功能，一期验证后追加）

- **时空胶囊**：广场（公开）/ 详情 / 创建 / 我的与收到的 / 点赞 / 设为公开 / 删除。
- **听歌识曲**：录音 → `POST /api/recognize` → 展示识别结果并可播放。

### 明确排除项

- 桌面歌词/桌面字幕（小程序无桌面）；评论回复、评论点赞（后端现为扁平评论，无子级）。
